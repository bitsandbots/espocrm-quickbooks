# Architecture

## Overview

The EspoCRM QuickBooks Integration is a standalone module that installs into an existing EspoCRM 9.x instance. All code lives inside `custom/Espo/Modules/QuickBooks/` (server-side) and `client/custom/modules/quick-books/` (frontend) — no EspoCRM core files are modified.

## Request Lifecycle

```
Browser → HTTPS (nginx :8443) → index.php → Slim Router
  → EspoCRM DI Container
    → Controller / Hook / Job
      → QuickBooksService
        → QuickBooks Online API (api.quickbooks.intuit.com)
```

EspoCRM uses constructor-injection via `InjectableFactory`. Services are instantiated on demand — hooks call `$this->injectableFactory->create(QuickBooksService::class)` rather than holding a persistent reference.

## Sync Architecture

### Real-Time Push (Hooks)

Triggered whenever a user saves an Account, Contact, or Invoice.

```
User saves entity
  → EspoCRM ORM persists to MySQL
  → Hooks::afterSave fires (order 20)
  → Loop guard: if $options->get('skipQuickBooksSync') → return
  → QuickBooksService::upsertCustomer() or upsertInvoice()
    → POST to QB API
    → QB returns Id + SyncToken
    → entityManager->saveEntity($entity, ['skipQuickBooksSync' => true, 'silent' => true])
```

The `skipQuickBooksSync` save option prevents the re-entrant save from triggering the hook a second time, avoiding an infinite loop.

### Nightly Pull (SyncFromQuickBooks)

Scheduled via EspoCRM's job system. Recommended: `0 2 * * *`.

1. Reads `lastSyncAt` from Integration entity. Defaults to 7 days ago on first run.
2. Queries QB: `SELECT * FROM Customer WHERE MetaData.LastUpdatedTime >= '$sinceDate'`
3. For each Customer: finds matching Account by `qbCustomerId`. Applies name/email/phone if QB timestamp is newer than `qbSyncedAt`.
4. Queries QB: `SELECT * FROM Payment WHERE TxnDate >= '$sinceDate'`
5. For each Payment: traces linked Invoice IDs, sets matching EspoCRM invoices to `status = Paid`.
6. Updates `lastSyncAt` and `lastSyncError` on Integration entity.

### Nightly Reconcile (ReconcileQuickBooks)

Scheduled via EspoCRM's job system. Recommended: `0 3 * * *` (after SyncFromQuickBooks).

1. Queries all Accounts where `qbCustomerId IS NOT NULL`, batch of 50.
2. For each: if `modifiedAt > qbSyncedAt`, push via `upsertCustomer()`.
3. Queries all Invoices where `qbInvoiceId IS NOT NULL` and status is not Paid or Voided, batch of 50.
4. For each: if `modifiedAt > qbSyncedAt`, push via `upsertInvoice()`.
5. Stores any errors in `Integration.lastSyncError`.

## OAuth 2.0 Flow

```
1. Admin opens Admin → Integrations → QuickBooks
2. Admin clicks "Connect to QuickBooks"
3. JS: POST /api/v1/QuickBooksIntegration/initOAuth
     → Server generates random state token (bin2hex(random_bytes(16)))
     → Stores state on Integration entity
     → Returns state to browser
4. JS opens popup to:
     https://appcenter.intuit.com/connect/oauth2
       ?client_id=...&scope=com.intuit.quickbooks.accounting
       &redirect_uri={siteUrl}/?entryPoint=QuickBooksOauthCallback
       &response_type=code&state={state}
5. User authorizes in Intuit UI
6. Intuit redirects to ?entryPoint=QuickBooksOauthCallback&code=...&realmId=...&state=...
7. QuickBooksOauthCallback:
     a. Verifies state matches Integration.oauthState (CSRF protection)
     b. POSTs code to https://oauth.platform.intuit.com/oauth2/v1/tokens/bearer
     c. Stores accessToken, refreshToken, accessTokenExpiresAt, realmId, connectedAt
     d. Clears oauthState
     e. Renders HTML that postMessages {name:'quickBooksOAuth', status:'success'} to parent
        window (restricted to siteUrl origin — not wildcard)
8. Admin view receives postMessage, refreshes model, re-renders status section
```

## Token Refresh

`QuickBooksService::getAccessToken()` is called before every API request:

1. Reads `accessTokenExpiresAt` from Integration entity.
2. If expiry is within 30 seconds: calls `refreshAccessToken()`.
3. `refreshAccessToken()` POSTs to the token endpoint with `grant_type=refresh_token`.
4. Stores new `accessToken`, `accessTokenExpiresAt`. If QB returns a new refresh token, updates `refreshToken`.

QB access tokens expire after 1 hour. Refresh tokens are valid for 100 days; failure to refresh within that window requires re-authorization.

## Conflict Resolution

`ConflictResolver` implements last-modified-wins:

| QB LastUpdatedTime | EspoCRM qbSyncedAt | Result |
|---|---|---|
| More recent | — | `WINNER_QB` — skip push, accept QB data |
| — | More recent | `WINNER_ESPO` — push to QB |
| Equal or older | — | `WINNER_ESPO` |
| null | null | `WINNER_NONE` — do nothing |

Used in `pullCustomersSince()`: if a matching Account's `qbSyncedAt` is equal to or newer than QB's `LastUpdatedTime`, the pull is skipped (EspoCRM already has this state or newer).

## Frontend

Source files are ES module classes in `src/`. They are transpiled to AMD format using EspoCRM's `js/transpile.js` node script. The transpiled files in `lib/transpiled/src/` are what the browser loads.

`module.json` sets `"jsTranspiled": true`, which tells EspoCRM to resolve module paths from `lib/transpiled/src/`.

| View | Purpose |
|------|---------|
| `views/admin/integrations/quick-books.js` | Extends EspoCRM's standard integration edit form. Adds OAuth Connect button, Sync Now button, connection status, last-sync time, and last-sync error display. |
| `views/panels/quick-books-status.js` | Side panel injected into Account and Contact detail views via `clientDefs`. Shows QB Customer ID (linked to QB app), last sync timestamp. |

The admin view uses `Espo.Ajax.postRequest` to call the custom API routes registered in `routes.json`.

## Background Job System

EspoCRM dispatches scheduled jobs via `cron.php`, which must run every minute:

```
* * * * * php /path/to/espocrm/cron.php > /dev/null 2>&1
```

Jobs implement `JobDataLess` and expose a `run()` method. They are registered in `Resources/metadata/app/scheduledJobs.json` and enabled via Admin → Scheduled Jobs.

## Error Handling

| Layer | Failure Mode | Impact |
|-------|-------------|--------|
| Hook (afterSave) | Logged at `warning` level | User save completes; QB sync silently fails |
| Job (run) | Logged at `error` level | Error stored in `Integration.lastSyncError` |
| Token refresh | Throws `Error` | Propagates to hook/job error handler |
| OAuth callback | Renders error HTML to popup | Admin sees inline error message |

Hooks are intentionally non-fatal: a QB API outage should never block users from saving records in EspoCRM.

## Data Integrity

- **SyncToken**: QB's optimistic concurrency token. Stored on each synced entity. Sent on updates; mismatch means QB rejects the update (stale client), prompting a re-fetch.
- **`sparse: true`**: QB sparse updates only write the fields included in the payload — no accidental field clears.
- **`skipQuickBooksSync`**: EspoCRM save option that prevents hook re-entry during QB field write-back.
- **`silent: true`**: Prevents modification audit trail entries when writing QB sync fields back to EspoCRM entities.
